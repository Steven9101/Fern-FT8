# Where the protocol comes from, and licences

Fern-FT8 is GPL-2.0-or-later (`LICENSE`). It is an independent
implementation: no code from WSJT-X, ft8_lib, ft8mon or any other decoder
was copied or translated. This page lists what was taken from where.

## The protocol definition (public domain)

S. Franke K9AN, B. Somerville G4WJS and J. Taylor K1JT, "The FT4 and FT8
Communication Protocols", QEX July/August 2020, pp. 7-17, cited in the code
as [QEX]. Its section 9 places the protocol description in the public
domain on conditions: the names FT4 and FT8 only for implementations that
follow the protocol definitions for source encoding, error-correction coding
and modulation; robotic or unattended QSOs must be disallowed; unassigned
message types stay reserved. Fern-FT8 follows the definitions, only
receives (it cannot transmit over the air; `fern-ft8 encode` writes WAV
files for tests), and refuses every message type the paper does not define
(0.2, 0.6, 0.7, 6 and 7).

The paper's reference [14], `ft4_ft8_protocols.tgz`, holds the
machine-readable parts. It is in `protocol/`, unchanged; `protocol/README.md`
gives the download and its SHA-256.

| protocol element | source | where in Fern-FT8 |
|---|---|---|
| LDPC (174,91) generator matrix | `protocol/generator.dat` | `src/protocol_tables.cpp`, generated by `tools/gen_tables.py`; `make check-tables` compares |
| LDPC parity-check matrix | `protocol/parity.dat` | same |
| CRC-14, polynomial 0x6757, initial 0, over 82 bits | [QEX] section 3, `protocol/gen_crc14.f90` | `src/protocol.cpp` |
| Costas array 3,1,4,0,6,5,2 at symbols 0, 36, 72 | [QEX] section 4 | `src/protocol.h` |
| Gray map of 3 bits to 8 tones | [QEX] Table 3 | `src/protocol.h` |
| GFSK, BT = 2, h = 1, 0.16 s symbols, 6.25 Hz, raised-cosine ramps of T/8 | [QEX] section 5, equation 3 | `src/gfsk.cpp` |
| message types, bit fields, c28 token values | [QEX] Tables 1, 2, 7 and Appendix A | `src/message.cpp` |
| standard call, grid, free text, nonstandard call encodings | `protocol/std_call_to_c28.f90`, `grid4_to_g15.f90`, `grid6_to_g25.f90`, `free_text_to_f71.f90`, `nonstd_to_c58.f90` | `src/message.cpp` |
| callsign hash, 47055833459 modulo 2^64 | `protocol/hashcodes.f90` | `src/callsign_hash.cpp` |
| ARRL/RAC sections, states and provinces | `protocol/arrl_rac_sections.txt`, `states_provinces.txt` | `src/protocol_tables.cpp` |

Both tables in the last row have changed since 2020. The changes were
established without reading WSJT-X's code: by packing a message with each
word using WSJT-X 2.7.0's `ft8code` program and reading the field value from
its output, as `tools/gen_tables.py` records:

- sections 16, 25 and 44 are now GH, NS and TER (RAC's 2023 changes); 85 PE
  and 86 NB were added;
- exchange values 8066 to 8171 are DR, FR, GD, GR, OV, ZH, ZL and X01 to X99.

## Behaviour matched by observation

Where the public-domain material is silent, Fern-FT8 matches what WSJT-X
does, established by running WSJT-X 2.7.0-rc3's programs and comparing
outputs, not by using its code:

- The printed form of each message type, word for word, and the bits of
  82 messages covering every type: `tests/vectors/ft8code.txt`, the output
  of `ft8code` recorded by `tools/make_vectors.py`. Two findings from those
  vectors: WSJT-X sends RR73 as the locator value of "RR73" (the
  public-domain `grid4_to_g15.f90` gives it a value of its own; Fern-FT8
  reads both and sends the first), and it right-justifies a nonstandard call
  in its 58-bit field (`nonstd_to_c58.f90` left-justifies; Fern-FT8 reads
  both and sends the first).
- `jt9`'s output line (`HHMMSS SNR DT FREQ ~ MESSAGE`) and its default
  search range, 200 to 4000 Hz.
- Decoding thresholds and decode counts, measured with `jt9` and `ft8sim`
  as a comparison, not as a source.

The research notes this work started from read WSJT-X's source (GPL-3.0)
to understand how it decodes, and so did its author, to learn which message
forms WSJT-X accepts (for example that it hides rover /R messages outside
contest mode). Ideas and published parameters are not protected by
copyright; the implementation here is Fern-FT8's own, and where it follows
WSJT-X's choices it says so in a comment. Its algorithms come from the
literature:

- noncoherent block detection over 1 to 3 symbols: M. K. Simon and D.
  Divsalar, IEEE Trans. Commun. 41(1), 1993, pp. 90-98, as [QEX] section 6
  describes its use;
- belief propagation (min-sum) and ordered statistics decoding: S. Lin and
  D. J. Costello, "Error Control Coding", 2nd ed., 2004;
- subtraction of decoded signals with a time-varying complex gain: [QEX]
  section 6.

The frequency and time refinement from symbol phases, the spectrogram
pre-check of candidates, the acceptance rules for OSD results, the noise
estimate and the four-lane belief propagation are Fern-FT8's own; the
measurements behind them are in `docs/DESIGN.md`.

## Test data

`tests/data/` holds three recordings from ft8_lib's test set (MIT licence,

## FernSDR

Fern-FT8 is a separate program that FernSDR (AGPL-3.0-or-later) will start
and talk to over pipes, as its `docs/MODULES.md` describes; the two
licences stay independent.
